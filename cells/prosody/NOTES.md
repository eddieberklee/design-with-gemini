# Live Voice Prosody Button Sizer (`cells/prosody/`)

Interactive Cell #2 prototype mounted into `#cell-prosody` in [index.html](../../index.html). Uses the **Gemini Live API** (`BidiGenerateContent` WebSocket) to stream continuous 16kHz PCM mic audio, show detected words in a live marquee, and resize a centered button with synthesized tactile sound feedback. Without a key, the three demo chips drive the same resize path.

## 1. Intent & Architecture

- **Core thesis**: Continuous streaming lets you speak naturally (*"a little smaller… a liiiittle smaller… MUCH bigger"*) and watch + hear the button respond live as vocal stress and elongation are detected.
- **Module graph (`window.GeminiProsody`)**:
  - [client.js](client.js) — `KeyStore` shares `dc_gemini_api_key_session` / `dc_gemini_api_key_local` with Cell #1 (`GeminiDecisions`) and Cell #4 (`GeminiApiMatrix`), dispatching `'gemini-key-changed'`, falling back to an in-memory key when storage access throws, and exposing `getStorageType()` with the same contract as `GeminiApiMatrix.KeyStore.getStorageType`; `createLiveSession` opens a `BidiGenerateContent` WebSocket (`models/gemini-3.8-live` with one fallback to `models/gemini-live-2.5-flash-native-audio`), enables `inputAudioTranscription`, resamples and streams 16kHz PCM chunks (`downsampleTo16k` + `floatTo16BitPCMBase64`, `sendPCM()` returns `boolean` so backpressure drops are distinguishable), and normalizes `adjust_button_size` tool calls (`normalizeToolArgs`: unknown direction → `none`/0, magnitude clamped to 40, sign forced by direction); `SoundFX` synthesizes pitched Web Audio resize ticks/chimes, creates its `AudioContext` lazily on the first sound (always inside a click or a live callback after the mic click), and closes it on mute (`toggleMute`) and on `close()`.
  - [ui.js](ui.js) — `UI.mount` adds `ui-tile` to `#cell-prosody` and renders the shared tile anatomy (`ui/NOTES.md` §2): `header.ui-tile-head` (index `02`, title, `button.ui-pill.ps-badge` status pill, `SFX` and `Reset` as `ui-btn ui-btn--sm`), the key popover, the stage (`.ui-tile-body--flush.ps-stage`: quiet size readout, delta readout, the hero `Confirm` button with a ghost outline of the previous size, transcript strip `.ps-marquee`), the controls (`.ps-controls`: mic `ui-btn ui-btn--sm`, HiDPI level canvas, demo phrases as `ui-chip`), and `footer.ui-tile-foot` (status line + `TX`/`RX`). Returns an idempotent `unmount()`. The `ps-` class on every element is kept as the test/selector hook next to the `ui-` classes.
  - [prosody.css](prosody.css) — Only what `ui/base.css` does not cover: stage (well + faint dot grid), hero button and ghost, transcript strip, control grid, key popover. Colours, sizes, radii and fonts are `--ui-` tokens; the one cell token is `--ps-morph` (280 ms hero resize, longer than `--ui-dur` so the size change and ghost read). Container steps query `ui-tile` (no own container name): `< 386px` one control row (mic + phrases scrolling sideways with a right-edge fade, level canvas hidden) and Reset leaves the header; `< 320px` compact (SFX hidden; transcript strip hidden so the button keeps its height; the mic + phrases row stays, with `.ps-compact-status` under it carrying the status line because base hides the foot; key description hidden); `< 240px` tiny (header = index + title + status dot with 4 px gaps, tile = header + stage, key popover covers the tile). The status hint names the phrases (`IDLE_HINT`) and both status lines exist only where the phrases are shown, so it never points at a hidden control.
  - [prosody.test.js](prosody.test.js) — `node:test` suite. Loads `client.js` + `ui.js` into a `vm` sandbox with a small fake DOM, fake storage, fake `WebSocket`, fake `AudioContext` and fake `getUserMedia` (no real socket or mic).

## 2. Hazards, Constraints & Lifecycle Invariants

- **Scale mapping & clamps (`ui.js:applyProsodyResult`, `ui.js:computeButtonDims`, `ui.js:stageInnerBox`)**: scale is clamped to `MIN_SCALE 0.45`..`MAX_SCALE 1.85`. The delta pill shows the change actually applied (`+8%` when a `+26%` request hits the clamp), the readout appends `clamped to max/min N%`, and a request at a clamp shows `MAX`/`MIN`, says "Already at max/min size", and hides the ghost (nothing changed). Non-finite `delta_percent` is treated as 0. Pixel size uses one fit ratio for the whole range: if the 185% button does not fit the stage's padded inner box, every scale shrinks by the same factor, so each step stays visible rather than saturating at the edge. `stageInnerBox` reads the stage's computed padding; the CSS padding reserves the metrics corner / delta pill (top) and marquee (bottom) at each `@container` step, so keep padding ≥ those overlays when changing either. Floors (`56×22`, lowered to the inner box when smaller) still apply. At the tiny step the controls and foot are hidden and the stage takes their height: at a 390 px page (tile 177×133, stage 175×101) 100% is 86×28 and 185% is 159×51; with Motion's slider at minimum (tile 140×105, stage 138×73) 100% is 66×22. Every phrase step changes the pixel size (`prosody.test.js` "tiny tiles").
- **Reset (`ui.js` reset handler)**: returns to exactly 100%, hides and empties the delta pill, hides the ghost, restores the marquee placeholder (`clearMarquee`), and reports the real rendered px size.
- **Key entry (`ui.js:saveKeyFromInput`, `ui.js:keyInputProblem`)**: blank / whitespace-only input and keys with inner spaces are rejected with an inline notice; they never clear or store a key. (The single-line password input already strips pasted line breaks before `keyInputProblem` sees the value.) (Clear is the only way to remove it). Save keeps `local` persistence when the key was stored as "remember on this device" by api-matrix. Escape is handled once, by the panel `keydown` listener; focus returns to the badge. The popover has `max-height` + `overflow-y: auto`, hides its description at compact width and covers the whole tile at tiny width, so Close and Save are in view without scrolling at a 390 px page.
- **Status pill truthfulness (`ui.js:syncBadge`, `BADGE_STATES`)**: `Demo` idle (no key; phrases simulate), `Key set` idle grey (key saved, not streaming), `Starting` rust (mic request + socket opening; `startLiveStream` calls `syncBadge` after `state.connecting = true`), `Live` green only while a Live session is ready and streaming. `syncBadge` also sets the pill's `data-tip` and `aria-label` (the label is hidden at tiny size) and the mic's state-dependent `data-tip`; every key/stream change (`onKeySync`, save, clear, start, ready, stop) goes through it. The mic gets `data-tone="attention"` only in `onReady` and loses it in `stopLiveStream`.
- **Tooltips (`ui/tooltip.js`)**: every control and non-obvious readout has a `data-tip` (pill, SFX on/off via `syncSfx`, Reset, key Close with Esc keycap, Clear, Save with Enter keycap, Confirm, size and delta readouts, transcript strip, level canvas, mic, each phrase via `CHIP_TIPS` keyed by preset id, TX/RX). The status line gets a `data-tip` with its full text only when it is truncated (`renderReadout`). No `title` attributes remain. The key input has no tip on purpose: `openKeyPanel` focuses it.
- **Key changes during a session (`ui.js:onKeySync`)**: `gemini-key-changed`, `storage` and window `focus` all call `onKeySync`. An open or connecting session compares `KeyStore.get()` with `state.sessionKey` (the key it started with) and stops when the key was changed or removed elsewhere; repeated events for the same key are no-ops.
- **Browser WebSocket `?key=` (`client.js:createLiveSession`)**: the browser `WebSocket` API cannot set upgrade headers, so `BidiGenerateContent` takes `?key=` in the URL. This cell never logs the URL, raw frames or the key, and never writes the key into the DOM outside the password input's `value`. Browsers may print a failed WebSocket's full URL (including `?key=`) in DevTools; that is outside page control and has not been observed for this cell. Transcripts and server error strings are rendered as text in the marquee and readout (and the readout's `data-tip` when truncated).
- **WebSocket fallback & backpressure (`client.js:createLiveSession`)**: each attempt captures `const sock`, arms a 12s setup timeout, detaches handlers before falling back once to the second model (stale callbacks from the first socket are ignored), drops PCM frames when `ws.bufferedAmount > 262144`, ignores non-object / non-JSON / undecodable frames, decodes `string`, `Blob`, `ArrayBuffer` and typed-array frames, and re-checks `closed || sock !== ws` after async `Blob.text()`. There is no reconnect after a session that reached `setupComplete` closes. If `createLiveSession` fails synchronously, `startLiveStream` does not store the dead session (epoch check right after the call).
- **3-tier live transcription (`ui.js:startLocalSpeechMirror`, `ui.js:stopLocalSpeechMirror`)**:
  1. **Primary (`inputAudioTranscription`)**: `inputTranscription` / `interimInputTranscription` update the marquee and stop the browser mirror on the first Gemini transcript.
  2. **Browser mirror (`SpeechRecognition` / `webkitSpeechRecognition`)**: low-latency local words before Gemini transcription arrives. Streams mic audio to the browser vendor's speech service, missing in Firefox, restricted on `file://`, and subject to dual-mic contention on Safari. Stopped on fatal `onerror` codes, `rec.start()` throws, or after 3 consecutive `onend` restarts (250ms backoff) without a result.
  3. **Tool-call fallback**: when neither is active, `onResize` writes the tool call's `transcript` into the marquee.
- **Teardown (`ui.js:stopLiveStream`, `ui.js:mount`)**: a monotonic `sessionEpoch` is bumped on every stop and checked in every async callback. `stopLiveStream` cancels the rAF, stops the speech mirror, closes the session socket, disconnects processor / gain / source / analyser, stops tracks and closes the capture `AudioContext`. It runs on the mic button, server close, track end, key change, `visibilitychange` to hidden (no automatic restart; the user clicks Start again), `pagehide`, and `unmount()`. `UI.mount` auto-cleans a prior mount on the same container and re-fits on `ResizeObserver` (stage) and window `resize`.
- **Sub-16 kHz resampling (`client.js:downsampleTo16k`)**: invalid rates (≤0, NaN, Infinity) return an empty buffer; `< 16 kHz` input is linearly interpolated (last sample held); `> 16 kHz` input is box-averaged; non-finite samples count as 0.

## 3. How to Run & Verify

1. Syntax check and tests (Node 22 does not accept a bare directory for `--test`; pass the file):
   ```bash
   node --check cells/prosody/client.js && node --check cells/prosody/ui.js
   node --test cells/prosody/prosody.test.js
   ```
2. Open `index.html` from `file://` or serve it (`python3 -m http.server 8000`).
3. Without a key: click each demo phrase (88% → 85% → 108% from 100% on a wide tile), hammer "MUCH bigger" (stops at 185%, delta `MAX`, ghost hidden), then Reset (100%, placeholder transcript). Click the `Demo` pill → Save with an empty field (inline notice, key unchanged). Hover each control: one tip each.
4. With a Gemini API key: the pill reads `Key set` (grey). Click `Start mic`: pill `Starting` (rust; the mic reads `Connecting…`), then `Live` (green) and the mic turns rust `Stop mic`; words flow into the transcript strip with `TX`/`RX` telemetry, and the button resizes on spoken commands. Hide the tab: the stream stops with a readout explaining why.
5. Layout: 1600, 1280, 1100, 900, 768, 390 and 360 px pages and Motion's slider at minimum and maximum. Nothing leaves the tile; size readout, delta, button and transcript never intersect. At 320–385 px tiles the phrase row scrolls sideways (fade on the right edge, `is-overflowing`).
