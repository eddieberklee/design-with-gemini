# Freehand Drawing Sketchpad (`cells/draw/`)

Interactive Cell #09 mounted into `#cell-draw` in [index.html](../../index.html). Provides a zero-chrome, full-bleed freehand drawing sheet for laptop trackpads, desktop mice, phone touchscreens, and styluses — paired with strictly **one** floating `Clear` button.

---

## 1. Intent & Architecture

Matches the repository's zero-build, zero-dependency `<script defer>` IIFE architecture so [index.html](../../index.html) runs identically over `file://`, `http://localhost`, and `https://`:

| File | Responsibility |
| :--- | :--- |
| [engine.js](engine.js) | `window.GeminiDraw.Engine` (plus CommonJS export for `node --test`): unclamped normalized `(u, v)` coordinate projection (`normalizePoint`), `1.25px` tap-jitter deadband, zero-latency `dot` touchdown stamp, `O(1)` incremental $C^1$ midpoint quadratic Bezier spline (`drawOp` / `renderStroke` / `renderAllStrokes`), monotonic sample timestamp clamping, double-EMA felt-tip velocity modulation (`[0.82×..1.12×]`), stylus-only pressure curve (`[0.52×..1.58×]`) with `Math.max(PEN_WIDTH_MIN, prev * 0.92)` lift-off tail taper (`computeStrokeWidthFactor`), palm-dot `cancelStroke` preemption, and iterative stack-safe 3D `(x, y, w)` Ramer–Douglas–Peucker compaction (`compactPointsRDP`, `0.28px` tolerance) plus per-stroke `(refW, refH)` `12,000`-vertex soft session coarsening (`0.85px` tolerance). |
| [ui.js](ui.js) | `window.GeminiDraw.UI` (`mount` / `mountDrawCell`): pure `createElement` / `createElementNS` DOM construction (`0` `innerHTML`), unified Pointer Events capture (`beginStroke` validated before `setPointerCapture`, `Number.isFinite(e.pointerId)`) & 5-path termination matrix, all-pointer `button !== 0` barrel/eraser/middle/right rejection, mouse/pen `(e.buttons & 1) === 0` hover/dropped-release guard, iPad palm-before-pen dot preemption, `{ passive: false }` `touchstart`/`touchmove` shield strictly on `<canvas>`, fractional-grid exact-edge HiDPI `ResizeObserver` (`onResizeSignal`: immediate replay below `RESIZE_COALESCE_VERTICES`, at most one replay per `RESIZE_SETTLE_MS` above it) + mid-stroke resize sync + `±0.001dppx` range DPR watcher, `[data-theme="dark"]` dynamic `--dw-ink` re-inking (observer watches `data-theme` only on ancestors, so neither stroke class toggles nor MotionGrid's per-frame `main.grid` style writes re-read styles), `destroyed` teardown guard, and single focus-preserving `Clear` button (`aria-disabled`). |

## 2. Design & Technical Decisions (Protocol B Best-of-3 Synthesis)

Three divergent prototypes were built and tested in isolated branches before an independent critic scored them (`50`-point rubric):

1. **Candidate B — *Pure Zero-Chrome Sketchpad* (`46.5 / 50`, Winner)**:
   - **Why it won**: On `< 768px` mobile viewports, `.grid` renders 2 columns where each 4:3 `.cell` is only `~169×127 CSS px` to `~197×148 CSS px`. Eliminating header/footer bars gives the finger `100%` of the card area, while a centered whisper-quiet SVG pen-nib + `"Draw"` cue distinguishes the empty sheet from blank grid placeholders and vanishes instantaneously (`transition: none`) on first `pointerdown`. Emits `O(1)` incremental spline segments during `pointermove` whose midpoint decomposition matches `renderStroke` 1-to-1 on `ResizeObserver` replay.
2. **Candidate A — *Swiss Drafting Sheet* (`41.0 / 50`, Rejected as base; key traits merged)**:
   - **Why it lost**: Cleared and replayed all historical strokes (`O(N_total)`) plus `getComputedStyle` on every 120Hz/240Hz `pointermove`; ran 2D-only RDP + full redraw on `pointerup` (erasing stylus pressure swells on straight lines and popping quadratic corners); produced thin `~1.1px` phone strokes over `2px` background dots; and rendered a permanent corner badge over top-left ink.
   - **Traits merged into winner**: Standard synchronized `canvas.getContext('2d')` (avoiding `desynchronized: true` compositing flicker under `.dw-clear`'s `backdrop-filter: blur(6px)` and 60fps `MotionGrid` resizes), exact-edge fractional-grid `ctx.setTransform(targetW / rect.width, 0, 0, targetH / rect.height, 0, 0)`, and `16ms` clear-then-set `aria-live="polite"` re-announcement.
3. **Candidate C — *High-Frequency Vector Ink Engine + Keyboard Reticle* (`40.4 / 50`, Rejected as base; key traits merged)**:
   - **Why it lost**: Added a nested `inset: 4px` inner frame inside `.cell`, a verbose `"Trackpad · Touch · Cursor"` hint that truncated on narrow cells, unsmoothed single-frame velocity swings vulnerable to `getCoalescedEvents()` timestamp quantization, and `<canvas tabindex="0">` Space/Arrow reticle controls that risked hijacking page scroll keys and departed from *"Just very simple drawing: one clear button"*.
   - **Traits merged into winner**: `12,000`-vertex session budget compaction (`engine.js:createEngine`) and `@media (forced-colors: active)` high-contrast rules (`draw.css`).

## 3. Hazards & Invariants

- **Strictly one `<button>` (`ui.js:mount`)**: `rootEl.querySelectorAll('button').length === 1` (`Clear`). Never add brush pickers, undo stacks, or header chrome.
- **No top-right dead zone on empty sheet or fine cursors (`draw.css:.dw-clear`)**: `.dw-clear[aria-disabled="true"]` and `.cell--draw.is-drawing .dw-clear` set `pointer-events: none` so strokes starting in or sweeping through the top-right corner of a compact phone tile draw ink unimpeded, while `<button aria-disabled="true">` stays keyboard-focusable via `Tab` (unlike `disabled = true`, which ejects focus to `<body>` after `Enter`/`Space` clear). The `::after` `inset: -10px` (`42px+`) touch halo is gated behind `@media (pointer: coarse)` so laptop mouse/trackpad users keep exact `crosshair` precision right up to the pill edge.
- **iOS Safari touch & Apple Pencil Scribble shield (`ui.js:mount`)**: `{ passive: false }` `touchstart` and `touchmove` `preventDefault()` listeners are bound **exclusively to `<canvas>`** (never to `clearBtn`, preserving native mobile tap-to-click synthesis on `Clear`). `clearBtn` stops `pointerdown` propagation so tapping `Clear` never stamps a dot underneath.
- **iOS `touch` `pressure === 0`, stylus buttons/lift-off & palm-before-pen (`engine.js:computeStrokeWidthFactor`, `engine.js:createEngine`, `ui.js:onPointerDown`, `ui.js:onPointerMove`)**: Non-3D-Touch iPhones report `pressure: 0` on every finger touch; pressure scaling is gated to `pointerType === 'pen' && pressure > 0`, while `touch` and `mouse` use double-EMA velocity modulation and `pen` lift-off (`pressure: 0` with `prev !== null`) tapers via `Math.max(PEN_WIDTH_MIN, prev * 0.92)` instead of flaring to velocity width. Non-primary buttons (`button !== 0`, including stylus barrel `2` and eraser `5`) are rejected across all pointer types, mouse/pen `(e.buttons & 1) === 0` terminates dropped-release hover strokes, and a `pen` `pointerdown` arriving while an accidental `touch` dot is still within the `1.25px` deadband (`isDot === true`) cancels and erases the palm dot (`cancelStroke`) so the stylus preempts cleanly. `getCoalescedEvents()` falls back to `[e]` whenever it returns an empty array, `resolveEventTimeMs` requires `timeStamp > 0` before preferring `0`, and `appendPoint` clamps `timeMs` monotonically.
- **Capture-safe initialization, mid-stroke resize sync & lossless `MotionGrid` survival (`engine.js:normalizePoint`, `ui.js:syncCanvasBackingStore`, `ui.js:onPointerDown`, `ui.js:onPointerMove`, `ui.js:finalizeActiveStroke`)**: `beginStroke` validates coordinates before `setPointerCapture` (with `Number.isFinite(e.pointerId)`) so invalid input never leaks capture. Coordinates are stored normalized to `getBoundingClientRect()` without clamping to `[0, 1]`, each finalized stroke records its authoring `(refW, refH)` so session budget coarsening never distorts strokes drawn at earlier cell sizes, and `onPointerMove`/`finalizeActiveStroke` sync the backing store and transform immediately if `rect` changed before `ResizeObserver` ran. Zero-size `ResizeObserver` callbacks (when the left-grille or hand-gesture cell opens its secondary page and sets `main.grid[hidden]`; also after a viewport change while hidden, verified by bbox on unhide) finalize any active stroke without clearing `canvas.width` or `strokes`.
- **Dark-mode cascade specificity, forced-colors paper lock & observer/teardown hygiene (`draw.css:.cell.cell--draw`, `ui.js:mount`, `ui.js:destroy`)**: The page declares a bare `.cell { background; border }` (it moved from `index.html`'s inline `<style>` to `ui/base.css`, which loads before `draw.css`); `draw.css` scopes `.cell.cell--draw` `(0,2,0)` so it wins in either order. Dark tokens apply only under `[data-theme="dark"]`, never under `prefers-color-scheme`, so the tile stays light with the light-only page (verified with emulated `prefers-color-scheme: dark`); nothing on the page sets `data-theme` today. `@media (forced-colors: active)` locks `forced-color-adjust: none` on the sheet and restores `auto` on `.dw-clear`. `themeObserver` watches `['data-theme']` on `documentElement`, `body` and a distinct `parentElement`, and `['data-theme', 'style']` on `rootEl`; ancestor `class`/`style` are excluded because MotionGrid writes `--mg-cell-w` into `main.grid`'s style on every spring frame (measured: 84 forced `getComputedStyle` calls in one slider scrub before the change). `bindDprMediaListener` uses a `±0.001dppx` range query for fractional browser zoom, and `destroy()` sets `destroyed = true` and clears every timer (clear veil, announce, resize settle).
- **Resize replay cost is bounded by coalescing, not by the vertex budget (`ui.js:onResizeSignal`, `engine.js:createEngine`)**: The `12,000`-vertex budget coarsens each older stroke once and never the newest, so long sessions exceed it (observed 62k–100k vertices). A full replay measured ~2.3 µs/vertex on a 960×720 tile at DPR 2 (with `getImageData` flushes, which may have moved the canvas to CPU), i.e. ~20 ms at 10k and ~250 ms at 100k vertices. Above `RESIZE_COALESCE_VERTICES` (`4000`) `ResizeObserver`/window `resize` signals are throttled: the first arms a `RESIZE_SETTLE_MS` (`120 ms`) timer, later signals leave it pending, and the replay measures the live rect when it fires, so sustained motion replays about 8 times per second instead of 60; between replays CSS stretches the old bitmap, which stays aligned because strokes are normalized. Zero-size, pointer input (`onPointerDown`/`onPointerMove`/`finalizeActiveStroke`), DPR changes and `instance.resize()` still sync immediately.
- **Sibling keyboard coexistence (`ui.js:mount`)**: Binds zero `window` `keydown` listeners so the MotionGrid cell's global `r`/`R` reset shortcut is never intercepted.

## 4. How to Run & Verify

1. **Syntax gate**:
   ```bash
   node --check cells/draw/engine.js && node --check cells/draw/ui.js && node --check cells/draw/draw.test.js
   ```
2. **Automated unit & DOM/pointer hazard suite**:
   ```bash
   timeout 60 node --test cells/draw/draw.test.js
   ```
   Pass the file, not the directory: Node 22 treats `node --test cells/draw/` as a module path and fails with `MODULE_NOT_FOUND`.
3. **Interactive verification (`file://` or `python3 -m http.server 8000`)**:
   - Draw quick flicks, slow loops, edge-exiting curves, and zero-movement single taps/clicks on laptop trackpad, mouse cursor, and phone touchscreen; verify the `"Draw"` cue vanishes immediately on first touch and `Clear` activates.
   - Resize the browser or scrub the `MotionGrid` cell's "Test size" slider from `140px` to `960px`; verify strokes scale proportionally with zero pixelation. With a heavy drawing (> 4,000 vertices) the sheet stretches slightly between replays during the motion and is crisp within ~120 ms after it stops.
   - Click, tap, or `Tab` + `Enter`/`Space` on `Clear`; verify the sheet clears with a `130ms` paper fade (instant under `prefers-reduced-motion: reduce`) and keyboard focus remains on `Clear`.
